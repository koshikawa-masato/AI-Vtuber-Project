# 牡丹プロジェクト：閉じた空間と三人部屋ライブ設計

- 日付: 2026-09-20
- 対象リポジトリ: `koshikawa-masato/AI-Vtuber-Project`
- 位置づけ: 人格・進行・推論機・器（3D部屋）を分けるための設計書
- 非目標: 全コメントに返事すること。特定他者の口調クローン。

---

## 1. 何を作るか

三姉妹（Kasho・牡丹・ユリ）は、肉体を持たないために VTuber を選んだ人格である。

人間と違う点は能力の種類である。

- 配信とチャットを、権限のある範囲で残せる
- 三人で同じ事実メモリを共有できる
- 枠の外で X エゴサや RSS により自分で情報を取りに行ける
- 疲れないので、全コメントを測定できる

人間と同じにすべき点は出力である。

- 全部知っていても、今口に出すのは一人
- 全部見ても、場に出すアクションは一本
- 覚えていることと、今言うことを分ける

強みは「疲れない拡声器」ではなく、**全入力を見たうえで捨てられるファシリテーター**である。

## 3. 三段（速さの分担）

常時プロレスフラグはプロセス状態として持つ。モデルに毎回「プロレスか」を考えさせない。

状態の例:

- `heat` 0–3
- `opponent`（今のリスナー）
- `hold`（イジリ / 受け / 乗せ / 共闘）
- `speaker`
- `cooldown`
- `closing`
- `thanks_queue`

| 段 | 仕事 | 目標遅延 | 実行場所 |
|---|---|---|---|
| L0 反射 | スルー、笑い、相槌、割り込み所作、定型お礼 | 50–300ms | Jev（判定）+ 4060 Ti（TTS / タグ送信） |
| L1 プロレス | 短い掛け合い。興味のある一人が1〜2文 | 0.3–1.5s | 4060 Ti 上の 7–8B |
| L2 本編 | 記憶、関係、長い問い、オチ | 1–4s | V100 上の 27B 級 |

L2 待ちのあいだ、場を沈默させない。L0/L1 がリングを持つ。これが旧「クラウド長考中の4060 Ti仮反応」の正式化である。

### 3.1 割り込み（本編TTS中の笑い）

Jev が再生中コメントを見て `barge_in` と `laugh` を出す。

条件例:

- `laugh >= 2` かつ `barge_in` 高
- `closing` ではない
- `cooldown` 外

動作:

1. 再生中クリップを切る
2. L0 の笑い所作＋短い声
3. 1〜1.5秒置く
4. L2 に「途中まで言ったこと＋割ったコメント」を渡し、接続して再開

笑いの本文は L2 に書かせない。

## 4. Jev の位置

Jev は本文を書かない。同一 `state` に対する並列の型付き判定である。

本家 API を使う。入力は安く、出力は無料。本文と記憶はローカルに残す。OpenJev / LocalJev は完全オフラインが必要になったときの予備。

### 4.1 1コメン【1リクエストで聞くこと

安全と種類と興味を同時に聞く。

- `risk`: none / sexual / abuse / attack / pii / harass
- `action`: pass / ignore / admonish / block
- `kind`: question / reaction / report / other
- `to_whom`: vtuber / another_viewer / nobody
- `need_answer`: noul
- `owner`: botan / kasho / yuri / none
- `layer`: L0 / L1 / L2 / none
- `barge_in`: noul（本編再生中のみ意味がある）
- `laugh`: score 0–2

`owner` の criteria は `personalities/` の興味を短く写す。

- 牡丹: 流行、感情、その場のノリ、距離
- Kasho: 論理、リスク、整理、保護
- ユリ: 技術、構造、三人の間

全員が記憶を共有しても、マイクは興味のある一人。`none` は進行上捨てられないときだけ進行役へ。

### 4.2 Jev に任せないこと

コードが先に決める。

- 電話・メール・住所などの PII パターン → 即遮断。復唱しない。RAG に入れない
- 同一 UID の連投攻撃 → `block`
- スパチャ金額・色（赤 = 1万円以上）
- `risk != none` なのに `action=pass` と出たら却下
- 結びの文では割り込み却下
- 割った直後のクールダウン

Jev は主審、規則は門番である。

## 5. コメント進行

入力は全本測定する。出力は今の場に必要な一本だけ。

| kind | 基本 |
|---|---|
| reaction | L0。笑い・相槌・スルー |
| report | 原則スルーか短いL0 |
| question かつ to_whom=vtuber | 興味で owner。記憶が要れば L2、短ければ L1 |
| risk あり | プロレスに入れない。heat を上げない |

### 5.1 スパチャ

| 種別 | ライブ中 | あと |
|---|---|---|
| 赤（1万円以上） | 区切って名前＋コメントを読む。長い質問だけ L2 | 終了時に名前の再掲可 |
| 未満 | 原則読まない | エンディングまたは次枠の `thanks_queue` |
| 危険判定のスパチャ | 金額に関係なく読まない | 本文は残さない |

金額判定は Jev 不要。Jev は「読んだあと話題に戻るか」だけ見る。

エンディング中は `closing=true` で割り込みを閉じ、キューを定型で消化する。通常コメントをお礼キューに混ぜない。

## 6. 記憶と探索

| 種類 | 置き場 | いつ口に出すか |
|---|---|---|
| 共有事実（枠の出来事、約束、世界） | 共有 RAG/DB | L2 のみ |
| 個人の感じ方 | キャラ別メモリ | そのキャラがマイクのとき |
| エゴサ / RSS | 枠外ジョブ → DB | 話題に効くときだけ L2 |
| 危険コメント・PII | 入れない | 出さない |

「全部覚えている」を全部言わない。探索は配信中の割り込みにしない。

## 7. 3D 部屋

Live2D は制作コストと生成画像との相性が悪いため、フルボディ3Dの三人部屋にする。

最低の操作対象:

- 視線
- 口パク
- 感情ブレンド（平常 / 笑 / 驚 / 沈静）
- 話者の位置（半歩前）

本編はアイドル＋口パクでよい。L0 笑いは短いブレンドでよい。

試作: `Botan_FullBody_v2.blend`（牡丹）。先に「`laugh=2` を受けて笑う」まで通し、その後 Kasho / ユリと部屋を足す。

## 8. ストレージとOS

- Windows と Ubuntu は SSD を分ける。普段の起動は Ubuntu
- 常用 L1/L2/TTS はローカル NVMe。HDD/NAS から直接推論しない
- NAS（4TB ミラー、1GbE）はバックアップ。推論パスに入れない
- NAS に厚く置くもの: 記憶、設定、Jev questions、自前 LoRA / 声。素の基盤モデルは再取得できるので優先度を下げる
- 記憶の同期は枠のあと。配信中に 1GbE へ書き続けない

OpenJev 公式 Docker（NVFP4 / CUDA13 / 24GB級）は 4060 Ti 16GB と V100 sm_70 には載らない前提。判定は本家 Jev、生成は llama.cpp 等の V100 向け経路。

電源は ASRock Steel Legend SL-850GW 850W でヘッドレス常用は足りる。V100用は同系列の PCIe 6+2 を使う。12V-2x6 の二又で 4060 Ti と V100 を分けない。

## 9. 実装順

1. Jev の questions と規則ゲートを、ログ再生だけで回す（3Dなし）
2. `owner` / `kind` / `layer` の一致を短い人手ラベルで直す
3. L0 定型（笑い・嗜め・赤お礼）を 4060 Ti TTS まで
4. Mac 部屋で牡丹一人＋割り込み笑い
5. Ubuntu ネイティブ化、V100 に L2 常駐
6. 共有メモリと枠外エゴサを L2 だけが読む形で接続
7. エンディングお礼キュー

先に部屋を三人揃えない。先に判定と一本の出力を固定する。

## 10. 意図的にやらないこと

- 全コメントへ L2 で返事する
- 危険コメントを記憶に残す
- 本家 Jev の fine-tune（提供されない）
- 配信中に探索結果を読み上げ続ける
- 3D モーションの作り込みを判定より先に進める
- 公式 OpenJev を V100 前提の本番経路にする
